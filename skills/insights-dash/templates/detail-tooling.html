The approach

Define 3–5 tools you want to actively use. A tool counts when it appears in your recent shell history — not just installed, but used. Update the list in growth-rules.md as your stack evolves.

Tool slots to consider

✓
AI coding assistant
Handles implementation, exploration, and refactoring. Your job is to direct it clearly.
✓
Terminal editor
For moments you need to take over. A modal editor (Helix, Vim, Neovim) keeps you in the terminal.
→
Terminal multiplexer
Splits your terminal into panes. Run your assistant in one pane and tests in another. tmux or Ghostty both work.
·
File navigator
Navigate the filesystem without leaving the terminal. yazi, ranger, or lf.
·
Shell config
Aliases for your most-typed commands. Don't do this until your other tools are comfortable — aliases before workflow is premature optimization.

How to score it

Count the tools that appear in tail -200 ~/.zsh_history (or your shell's history file). Installed but unused = 0. Used at least once this period = 1. Score = (used tools / total target tools) × 100.

# Check which target tools appear in recent history tail -200 ~/.zsh_history | grep -E 'hx|nvim|vim|tmux|yazi|ranger|claude' | sort | uniq -c | sort -rn

Getting started

  1. Pick one tool you don't use yet Add it to your target list in growth-rules.md with a shell command to detect it.
  2. Use it for one real task this period Don't try to master it — just get it into your history.
  3. Repeat when it feels natural After two periods of use, it should feel comfortable. Then add the next tool.

Copyable prompt

Ask Claude to help you set up a new tool:

I want to add [tool name] to my daily workflow. I already have [existing tools]. Help me: (1) install it, (2) configure it minimally to work with my current setup, (3) give me 3 tasks I can use it for this week to build the habit.
