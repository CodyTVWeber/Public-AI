Why it matters

  • When a session goes sideways, there's no checkpoint to roll back to
  • Without commits, Claude has no memory of what shipped — it can't reference prior decisions
  • Small, frequent commits make reviews easier and bad changes easier to revert

How to fix it

  1. Trigger: after tests pass Every time a test suite goes green, stop and commit before moving on. Don't wait for the feature to be complete.
  2. Tell Claude to commit End any implementation prompt with "commit when tests pass." Claude will do it if you ask.
  3. Build a /commit skill A skill that stages changes, proposes a conventional commit message referencing the ticket ID from the branch name, and waits for your approval.

Copyable prompts

Add to the end of any implementation prompt:

When tests pass, commit with a conventional commit message referencing the ticket ID in the branch name. Don't wait for me to ask.

Scaffold the /commit skill:

Create ~/.claude/commands/commit.md with these instructions: When invoked: run git status and git diff, group changes into logical commits, write a Conventional Commits message referencing the ticket ID from the branch name, show the proposed message and wait for approval before running git commit.
