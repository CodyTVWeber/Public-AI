Optimistic-rollback bug: bucket submit (BUCKET_LIMIT = 3), task #2 fails

Illustration of the "I do a bucket of actions and they seem to reset" report. Verified against src/config/constants.ts: BUCKET_LIMIT = 3, so a real bucket submit fires at most 3 concurrent mutations — the worst case here (2 of 3 siblings wiped) is the actual real-world ceiling, not a dramatized one. Left = current code (src/hooks/useTaskTransitions.ts, wholesale onError rollback). Right = fixed code (scoped per-task rollback). Same simulated network outcome on both sides — only the rollback logic differs.
3 tasks submitted concurrently (bucket max) · task #2 rejects after #1 and #3 already succeeded

Before fix BUG

Each mutation's onMutate snapshots the entire task array. When #2's onError fires, it replaces the whole cache with its own stale snapshot — wiping out #1 and #3, which already succeeded.

After fix FIXED

Each mutation's onMutate only remembers its own previousStatus. When #2's onError fires, it reverts only task #2 via setInstanceStatus — #1 and #3 are untouched.

The actual diff (src/hooks/useTaskTransitions.ts)

onError — before
onError: (err, vars, ctx) => {
  if (ctx?.previous)
    queryClient.setQueryData(
      instancesKey,
      ctx.previous // whole array, stale
    );
}
onError — after
onError: (err, vars, ctx) => {
  if (ctx?.previousStatus) {
    queryClient.setQueryData(instancesKey, (old) =>
      setInstanceStatus(
        old, vars.taskId,
        ctx.previousStatus, // this task only
        businessDate
      )
    );
  }
}
